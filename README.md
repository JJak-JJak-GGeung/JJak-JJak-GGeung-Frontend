# 짝짜꿍 · 식자재 대금 송금 전 대조 도우미

> **청구서대로 정말 받았나요?** 식당 점주가 식자재 대금을 보내기 전에, 거래처의 납품명세·점포 수령기록·청구서를 사진으로 대조하고 근거와 함께 직접 승인하는 서비스입니다.

**🔗 서비스 바로가기: https://jjak-jjak-ggeung-frontend.vercel.app**
회원가입 없이 바로 쓸 수 있습니다. 같은 기기·같은 브라우저 프로필로 다시 열면 저장한 자료가 그대로 보입니다.

| 저장소 | 내용 |
| --- | --- |
| **Frontend (여기)** | Flutter Web 점주 화면 |
| [Backend](https://github.com/JJak-JJak-GGeung/JJak-JJak-GGeung-Backend) | FastAPI · 사진 판독 · 음성 전사 · 대조 계산 |
| [Database](https://github.com/JJak-JJak-GGeung/JJak-JJak-GGeung-Database) | Supabase PostgreSQL 스키마 · 승인 트랜잭션 |

## 어떤 문제를 푸나요

식당은 매주 거래처에서 식자재를 받고 주말에 청구서를 받아 송금합니다. 그런데 종이가 여러 장입니다.

- **납품명세서** — 거래처가 "이만큼 보냈다"
- **점포 수령기록** — 우리 가게가 실제로 달아 본 양
- **청구서** — "이만큼 돈을 달라"

셋이 어긋나도 바쁜 점주는 일일이 대조하지 못하고 그대로 송금하기 쉽습니다. 짝짜꿍은 **근거 없이는 승인되지 않고, 승인한 것은 근거와 함께 남도록** 만듭니다.

## 원칙 · AI는 읽고, 규칙은 계산하고, 결정은 점주가 합니다

| 단계 | 누가 | 하는 일 |
| --- | --- | --- |
| 사진 판독 | **AI** (OpenAI 비전 모델 `gpt-4.1-mini`) | 문서 종류·거래처·명세 번호·품목·수량·단가를 읽고 원본 위치와 함께 제안 |
| 통화 메모 | **AI** (OpenAI 음성 전사) | 점주가 말한 통화 내용을 고칠 수 있는 초안으로 받아쓰기 |
| 차이·금액·승인 가능 여부 | **서버 규칙** | 같은 입력에는 항상 같은 결과. 근거가 빠지면 빈 값으로 두고 승인 차단 |
| 저장·승인 | **점주** | 판독값·메모·수령 연결·승인은 점주가 확인을 눌러야만 저장 |

## 2분 체험

### ① 가장 빠르게 · 합성 명세표로 연습
첫 화면의 **「합성 명세표로 연습」** → 예시 명세표 선택 → AI가 읽은 품목·수량을 원본과 비교 → 저장.

### ② 전체 흐름 · 차이 발견 → 통화 메모 → 수정 청구 → 승인
[`docs/samples/`](docs/samples)의 예시 자료를 내려받아 순서대로 진행합니다. (팀이 만든 가상 거래 자료입니다.)

| 파일 | 내용 |
| --- | --- |
| [A01_납품명세_1109.png](docs/samples/A01_납품명세_1109.png) | 11/09 납품 · 손질장어 60kg |
| [A02_납품명세_1113.png](docs/samples/A02_납품명세_1113.png) | 11/13 납품 · 손질장어 **40kg** (DL-A131) |
| [A03_점포수령기록.png](docs/samples/A03_점포수령기록.png) | 점포가 실제로 받은 양 · 60kg / **36kg** |
| [A04_주간청구서.png](docs/samples/A04_주간청구서.png) | 주간 청구 100kg · 2,000,000원 |
| [A05_수정청구서.png](docs/samples/A05_수정청구서.png) | 양측 확인 후 수정 청구 96kg · 1,920,000원 |
| [A06_통화뒤_점주음성_읽을문장.txt](docs/samples/A06_통화뒤_점주음성_읽을문장.txt) | 마이크에 읽을 통화 메모 문장 |

1. **사진 올리기** — A01~A04를 차례로 올리고 AI 판독값을 확인해 같은 점포·거래처·주에 저장합니다.
2. **수령 확인** — A03의 수령 줄을 각 납품에 연결하면 주간 **청구 100kg / 수령 96kg, 확인할 차이 +4kg · 80,000원**이 나타나고 승인이 막힙니다.
3. **통화 메모** — DL-A131 거래에서 **「말로 남기기」**로 A06 문장을 읽거나 **「통화녹음 올리기」**로 녹음 파일을 올립니다. 받아쓴 초안을 고쳐 저장하면 거래처 주장(40kg)과 점포 기록(36kg)이 나란히 남고 **확인 중**이 유지됩니다. 마이크가 없으면 **「직접 입력」**도 같은 경로로 저장됩니다.
4. **수정 청구** — A05를 올리고 이전 청구서를 대체하는지와 양측 합의 문구를 확인하면 **승인 대상 1,920,000원**이 됩니다.
5. **직접 승인 · 다시 보기** — 점주가 승인하면 당시 근거가 고정된 승인본이 생깁니다. 두 번 눌러도 한 건이며, **승인 내역**에서 언제든 다시 열 수 있습니다. 송금 여부는 별도라 **송금 미확인**으로 표시됩니다.

## 화면 구성

| 화면 | 역할 |
| --- | --- |
| 시작 | 점포·거래처·주 선택, 사진/통화녹음 올리기, 합성 명세표 연습 |
| 주간 정산 | 명세·청구·수령 합계, 확인할 차이, 승인 차단 사유 |
| 사진 확인 | AI 판독값과 원본을 나란히 보고 고친 뒤 저장 |
| 거래 상세 | 명세·수령·청구 원본 줄, 통화 메모(음성·직접 입력) |
| 승인 · 승인 내역 | 직접 승인, 당시 근거·금액·버전 재조회 |

## 기술 스택

Flutter Web 3.47 · Riverpod · GoRouter · `record`(브라우저 녹음) · Vercel 배포 → [Backend](https://github.com/JJak-JJak-GGeung/JJak-JJak-GGeung-Backend)(FastAPI · OpenAI API · Docker on AWS Lightsail) → [Database](https://github.com/JJak-JJak-GGeung/JJak-JJak-GGeung-Database)(Supabase PostgreSQL · Storage)

박승원이 Flutter Web·Riverpod·GoRouter 화면을 구현합니다. 이 저장소 루트가 Flutter 프로젝트이고 화면 코드는 `lib/`, 패키지 명세는 `pubspec.yaml`입니다. 개발 브랜치는 `screen-photo`입니다. 사진 판독 Python 코드는 Backend 저장소의 같은 이름 브랜치에 둡니다.

역할 브랜치에서 변경하고 이 저장소의 `main`을 대상으로 PR을 엽니다. PR에 직접 확인한 동작과 결과, 다음 담당자가 받을 값을 적습니다. 우영이 검토·병합하고 구본혁이 병합된 버전을 배포합니다. 팀 배포팩의 `frontend/`, `backend/`는 해당 저장소 루트를 뜻합니다. DB 변경은 Database 저장소로 보냅니다.
